Autoencoder-HIDS Sentinel Console

A host-based intrusion detection system for encrypted traffic. It never decrypts a payload: it captures live flows, extracts 22 behavioral features, reconstructs them through a neural network trained only on benign traffic, and raises an alert when the reconstruction error crosses a calibrated threshold. Alerts surface in a real-time PySide6 dashboard.

02 — Objectives

What we set out to do

General objective. Design and implement a standalone, containerized HIDS that uses an unsupervised autoencoder to detect hidden threats in encrypted network traffic through flow-based behavioral analysis.
01 · Feature extraction

Capture session metadata and timing features with no payload decryption, keeping the process low-intrusion and privacy-preserving.

02 · Model training

Train and optimize an autoencoder that models the benign baseline and detects anomalies through reconstruction error.

03 · Backend and forensics

Deploy the detection engine with FastAPI and Docker, with an integrated SQLite database for reliable forensic logging.

04 · Dashboard

Build a responsive PySide6 interface for live threat monitoring, alert visualization and analyst feedback.

The problem: over 95% of web traffic is encrypted, so signature-based deep packet inspection is effectively blind, and decrypting it raises privacy, legal and performance concerns.

05 — Data Pipeline

From raw packet to alert in five steps

1 · Capture

Scapy sniffs IPv4 on the chosen interface. Layer 3/4 headers only.

2 · Extract

Once a flow has 5+ packets, 22 behavioral features are computed.

3 · Normalize

log(1+x) then Min-Max to [0,1], using the saved scaler.pkl.

4 · Score

Encoder → bottleneck → decoder. MSE is the anomaly score.

5 · Alert

If MSE > τ, write to SQLite and emit a Qt signal. No polling.

Each flow also carries an is_encrypted flag, set from port patterns (443, 8443, 993, 995, 465, 587, 1194) and TLS header hints, without reading any payload. Encryption is never broken; the system only watches how a flow behaves.

06 — Feature Vector

22 payload-free behavioral features, six groups

Timing · 6

Volume · 5

Rate · 2

flow_pkts_per_sec flow_bytes_per_sec

Burstiness · 3

pkt_len_variance burst_ratio active_time_ratio

Session · 3

pkt_count unique_ttl_count ttl_mean

Protocol · 3

tcp_flag_ratio has_udp has_tcp

Feature check. Kolmogorov-Smirnov statistics, Random-Forest importance and mutual information showed 14 of the 22 features separate benign from malicious traffic (KS > 0.3), and all 22 were kept. Seven were approximated from CICFlowMeter columns for offline training; the live Scapy parser computes them directly.

Encode

The encoder squeezes 22 features into a 4-value summary of what normal flows look like.

Decode

The decoder rebuilds all 22 values. Trained on benign flows only, it rebuilds them well.

Score

Anomalous flows rebuild badly, so their mean squared error is high. MSE > τ raises an alert.

22-16-8-4-8-16-22 · 1,194 parameters · ReLU hidden layers, sigmoid output · BatchNorm, Dropout 0.1 · Adam (lr 1e-3), MSE loss, batch 512.

08 — Training & Threshold

Benign-only training, statistical threshold

458,936benign flows · training (70%)
98,343benign flows · threshold calibration (15%)
306,883test flows: 98,345 benign + 208,538 attack (14 types)
387 straining time, CPU-only laptop
τ = max( P99(RE_benign) , μ_benign + k·σ_benign )     # k = 3, fixed before testing
τ = 0.0242   (μ = 0.0026, σ = 0.0047)

The autoencoder never sees an attack during training or calibration, and attack labels are used only to score the test set. The threshold is set so about 1% of normal validation traffic exceeds it, which keeps false alarms low by design.
